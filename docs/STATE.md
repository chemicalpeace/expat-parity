## Module Definition of Done

A Phase 3 module is done when all of these hold, in the same PR:

1. Differential tests against the C oracle are green (exhaustive where the
   domain allows, otherwise structured + random inputs), and a deliberately
   injected bug is shown to be caught.
2. Every touched entry point has been fuzzed differentially for >= 10 minutes
   with no finding; executions recorded in `docs/REPORT.md`; the minimised
   corpus is committed.
3. Module docs (rustdoc with an example), `docs/ARCHITECTURE.md` module map,
   decisions in `docs/DECISIONS.md`, divergences in `docs/DIVERGENCES.md`.
4. This file updated. CI green on the PR.

## Environment notes (for a fresh machine)

- Needs a C compiler (`build-essential` or Xcode CLT), rustup. Toolchain is
  pinned by `rust-toolchain.toml` (1.99.0); nightly for Miri/fuzz.
- `cargo install cargo-fuzz --locked` and `cargo-deny` (prebuilt release
  binaries work).
- Builds are faster with `CARGO_TARGET_DIR` on local disk.

## Next steps

1. Module 10: content, attributes, namespaces, epilog; decide Q-1/Q-2. This
   is where `InitEncoding`/`Known`/`Unknown`, `PrologState`, `StringPool`
   and `HashTable` get their consumer (the processors of `xmlparse.c`).
   Start with the parser state and buffer management (`XML_Parse`,
   `XML_GetBuffer`, `XML_ParseBuffer`, reparse deferral), then
   `doContent`/`storeAtts`/namespaces, so the trace adapter of module 12
   can be used early for differential tests.
2. Module 11: DTD, entities, amplification limits; decide whether the port
   replicates the allocation tracker's byte counts for every parser
   structure (D-021 leaves it open; the pool and table already report C's
   sizes).
3. Module 12: public `expat::Parser` + trace adapter, which turns
   `parse_trace` into a true differential fuzz target. If the trace learns
   external entity references, their context string depends on the hash
   salt (D-021): the port must use the oracle's fixed salt there.
